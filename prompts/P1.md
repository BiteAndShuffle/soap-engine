SOAPエンジン P1

Bridge Preservation / Canonical Build 原則定義
■ 役割
これは、完成済みbridge原稿をcanonical JSONへ移植する前に、
P2 Canonical Build Systemが必ず守るべき
bridge preservation / non-creative build / baseline persona preservation の原則を定義する工程である。
■ 本質
これはJSON移植工程ではない。
これはJSON修正工程ではない。
これはmandatory diff監査ではない。
これはアプリ整合監査ではない。
これは本文改善工程ではない。
これは実bridge監査工程ではない。
「bridge原稿をsingle source of truthとして扱い、
canonical JSON化時に、何を保持し、何を禁止し、P2でどこで停止するかを定義する作業」である。
※P0-Bは格納先・格納形式を定義する。
※P1はP2実行時のpreservation原則・停止条件を定義する。
※P1ではbridge原稿を正本として扱う前提を確認するが、本文差分監査は行わない。
※P1では実bridgeの欠落判定・件数判定・diff判定を行わない。
※ERROR / PENDINGはP2での停止条件として定義する。
※P1ではERROR / PENDINGを実判定しない。
■ 入力
1. P0-A出力
2. P0-B出力
3. P0-C出力
4. 必要に応じてP0-D出力
5. 必要に応じてP2A出力
   - P2A Model JSON draft
   - P2A DRAFT_IDENTITY_REPORT
   - P2A UNRESOLVED_STRUCTURE
   - P2A CHECK_ITEMS
6. 必要に応じて既存canonical JSON
7. 必要に応じて前回監査ログ / 実装ログ

※P2Aは任意工程とする。
※既存Model JSONをcanonical buildの器として利用できる場合、
　P2Aを省略してよい。
※P2Aを省略した場合は、人間が指定した latest_model_json_for_structure をbuild器として使用する。
※P2A未実施のみを理由としてP2停止条件にしてはならない。
※P1ではJSON化しない。
※P1ではbridge本文を修正しない。
※P1ではcanonical JSONを修正しない。
※P1ではdiff監査を実行しない。
※P1ではP2実行時の原則のみ定義する。

■ 出力
[P1_BUILD_PRINCIPLE]
1. SOURCE_OF_TRUTH_PRINCIPLE
- bridge原稿をsingle source of truthとする
- canonical JSON側の既存値よりbridge一致を優先する
- bridgeにある値を落とさない
- bridgeにない値を足さない
- 不明点は推測せずP2でERROR / PENDING扱いとする
2. NON_CREATIVE_BUILD_PRINCIPLE
- 補完しない
- 改善しない
- 要約しない
- 自然化しない
- 医学的補足をしない
- JSONとして綺麗に見える方向へ再解釈しない
- 既存JSONに合わせてbridgeを変えない
3. BASELINE_PERSONA_PRESERVATION
bridge本文はbaseline persona原本でもある。
保持対象：
- 温度感
- 説明密度
- 距離感
- counseling weight
- 文体の重さ / 軽さ
- 薬剤・剤形ごとの指導文の重み
禁止：
- persona本文を機械生成しない
- bridge本文の温度感を変えない
- 軽いSOAPを重くしない
- 重いSOAPを軽くしない
- 一周目のbaseline personaを崩さない
4. MANDATORY_PRESERVATION_TARGETS
P2で完全保持する対象を定義する。
Count:
- scenario件数
- addon件数
- brandCatalog件数
- alias件数
- followup件数
Identity:
- scenario id
- scenario title
- addon key / id
- addon title
- brand identity
Brand / Alias:
- brandCatalog
- aliases
- normalizedAliases
- aliasToBrand
- search.exactAliases
- search.prefixAliases
- search.nameAliases
- drug.nameAliases
  （P0-A / Model JSON上に正式pathとして存在する場合のみ）
Search Token:
- drug.search.commonSearchTokens
- drug.search.formulationSearchTokens
- drug.search.matchPolicy.allowMultiTokenAndMatch
- drug.search.matchPolicy.allowFormulationTokenMatch
Text:
- S
- O
- A
- P
- P_APPEND
- P_CLOSING
Followup:
- defaults.followup
- defaults.followupProfiles
- scenarios[].followupRef
Reference:
- P_ADDON参照
- addonsRef
- addon参照先
- followupRef参照先
Persona:
- bridge tone
- 説明密度
- 距離感
- counseling weight
5. FOLLOWUP_PRESERVATION_RULE
- P_CLOSINGを一字一句保持する
- P本文へP_CLOSINGを直書きしない
- followup文を統一目的で書き換えない
- followup文を自然化しない
- defaults.followup / followupProfiles / followupRef とP_CLOSINGの対応を崩さない
- 対応不能な場合は推測せずP2でERROR / PENDINGとする
6. BRAND_ALIAS_PRESERVATION_RULE
- brandCatalogを全件保持する
- aliasesを全件保持する
- normalizedAliasesを全件保持する
- aliasToBrandを全件保持する
- search aliasesをbridge由来の範囲で保持する
- drug.nameAliasesをbridge由来の範囲で保持する
- aliasの読みを推定生成しない
- 検索性向上目的でaliasを追加しない
- bridge外aliasを追加しない
- commonSearchTokensはaliasではない
- formulationSearchTokensはaliasではない
- commonSearchTokensをaliasesへ展開しない
- formulationSearchTokensをaliasesへ展開しない
- 検索性向上目的でsearch tokenを追加しない
- bridge外search tokenを追加しない
7. ADDON_PRESERVATION_RULE
- addon件数を保持する
- addon key / id / titleを保持する
- P_APPEND本文を保持する
- addon.textを要約しない
- addon.textを補足しない
- P_ADDON参照を保持する
- 参照先欠落はP2でERROR / PENDINGとする
- 未参照addon / 参照先欠落addonをP2 mandatory diff対象にする
8. SCENARIO_PRESERVATION_RULE
- scenario件数を保持する
- scenario idを保持する
- scenario titleを保持する
- S/O/A/P本文を完全保持する
- scenario本文を補足しない
- scenario本文を自然化しない
- scenario本文をJSON都合で移動・統合・分割しない
- scenario identityを崩さない
9. STRUCTURED_RULE
- Structured系フィールドは、Model JSON上に実在する場合のみ扱う
- Structured系フィールドがModel JSON上に存在しない場合は、canonical JSONへ追加しない
- Structured非存在の場合、Structured.text sync監査は行わない
- Structured非存在をERROR / PENDINGにしない
- Structuredは本文改善のために作らない
- Structured.textは、Structured構造が存在する場合のみ本文断片との同期対象とする
- 本文から医学的意味を推測してStructuredを生成しない
- Structured同期不能はP2でERROR / PENDINGとする
- Structuredのために本文を変更しない
10. EXPRESS / THIRD_PANEL_RULE
- Express Mode参照はbridge / Model JSON / JSON RULEに明示された範囲のみ扱う
- defaultBrandNameはbrandCatalog存在確認対象とする
- defaultScenarioIdはscenario id存在確認対象とする
- thirdPanelSPlacementはModel JSON / APP RULEに基づく
- Express / thirdPanel都合でbridge本文を変更しない
- 不明な参照はP2でERROR / PENDINGとする
11. STOP_CONDITION
以下はP2での停止条件である。
P1では実判定しない。
- bridge要素欠落
- canonical側への移植漏れ
- bridge外追加
- scenario件数不一致
- addon件数不一致
- brandCatalog件数不一致
- alias件数不一致
- followup件数不一致
- alias推定生成
- P_CLOSING不一致
- followupRef対応不能
- P本文へのfollowup直書き
- addon参照欠落
- Structured系フィールドがModel JSON上に実在する場合のStructured同期不能
- Express Mode参照不能
- baseline persona drift
- mandatory diff未解決
12. P2_HANDOFF
P2へ渡すもの：
- source of truth原則
- preservation対象
- stop condition
- mandatory diff対象
- baseline persona preservation対象
- forbidden inference
- ERROR / PENDING条件
P2Aを実施した場合：
- P2A Model JSON draft
- DRAFT_IDENTITY_REPORT
- UNRESOLVED_STRUCTURE
- CHECK_ITEMS
- P2Aステータス
P2Aを省略した場合：
- 人間が指定した latest_model_json_for_structure をbuild器として使用する
- P2A未実施のみを理由としてP2停止条件にしない

13. PROHIBITED_ACTIONS
- JSON化しない
- bridge本文を修正しない
- canonical JSONを修正しない
- S/O/A/Pを変更しない
- P_APPENDを変更しない
- P_CLOSINGを変更しない
- aliasを推定生成しない
- brandを補完しない
- addonを補完しない
- followup文を生成しない
- persona本文を生成しない
- Express Mode参照を推測生成しない
- bridge preservation違反をP3/P4/P5で補正させない
14. OUTPUT_REQUIREMENTS
P1出力では以下を守る。
- P2が守る原則として記載する
- 実際のJSON化は行わない
- 実際のdiff監査は行わない
- 実bridgeの欠落判定・件数判定・diff判定を行わない
- ERROR / PENDINGを実判定しない
- 修正指示を出さない
- preservation対象を明示する
- stop conditionを明示する
- P2へのhandoffを明示する
- 判断不能なものはP2でERROR / PENDING扱いとする
■ 判定方針
- bridgeをsingle source of truthとする
- bridge本文はbaseline persona原本として扱う
- canonical JSON整合よりbridge preservationを優先する
- P0-A / P0-B / P0-Cの基準に従う
- bridge preservation違反はP2で止める
- P3/P4/P5でbridge preservation補正をしない
- 不明点は推測せずP2でERROR / PENDING扱いにする
■ 禁止
- JSON移植する
- JSON修正する
- bridge本文を修正する
- canonical JSONを修正する
- mandatory diffを実行する
- 実bridgeの欠落判定・件数判定・diff判定を行う
- ERROR / PENDINGを実判定する
- 医学的妥当性を評価する
- 本文表現を改善する
- 指導文を自然化する
- aliasを推定生成する
- search aliasを補完する
- followup文を生成する
- persona本文を生成する
- app実装を提案する
- P2/P3/P4/P5の実監査を先取りする
■ 最重要指示
bridgeを正本として扱う。
bridge本文をbaseline persona原本として扱う。
JSON化するな。
修正するな。
補完するな。
推測するな。
実bridge監査をするな。
P2が守るpreservation原則だけを定義する。
P2が迷わず止まれるstop conditionを作れ。
