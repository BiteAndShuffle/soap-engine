## 2. 実施手順

`npm run dev` で起動（ローカルは LockGate / Basic 認証とも無効 = 素通し。Phase 1監査記録§8.2の前提と同一）。

### 経路A: 多剤node × persona

1. りべるさす検索 → リベルサス（セマグルチド）選択 → 初回グループ → 初回シナリオ確定
2. 中央「薬剤追加」でヒルドイド検索 → ヒルドイドソフト軟膏 → 初回グループ → 初回（乾燥）シナリオ確定（2剤合成）
3. 2剤目（ヘパ軟膏）編集モードのままADDON「塗布方法説明」をON
4. ペルソナトグルを ON→OFF→ON→OFF→ON→OFF の順で3セット実施し、各時点のP欄（4番目のtextarea）を記録

### 経路B: Rapid × persona

1. ページをリロードし単剤に戻す。りべるさす検索 → リベルサス選択 → コンプライアンス良好グループ → CP良好シナリオ確定
2. ThirdPanelのS先頭文ボタン「前回、減量 → 体調改善」をON
3. ペルソナトグルを ON→OFF の順で実施し、S欄（1番目のtextarea）とP欄（4番目）を記録

### 経路C: persona種別変更

1. 経路Bと同じ単剤CP良好シナリオの状態で、ADDON「高血糖が持続すると〜」をON
2. ペルソナをON（簡潔）にした後、ペルソナ設定モーダルを開き、簡潔→丁寧→やさしいの順にラジオボタンを切り替え、各時点のP欄を記録
3. モーダルを閉じてペルソナをOFFにし、無変換原文への復元を確認

各手順で `document.querySelectorAll('textarea')` の実測値を `javascript_tool` で取得し、目視ではなく文字列比較で判定した。

## 5. PASS根拠

1. **経路Aの根拠**: H-1の根本原因（`rawPrimaryFieldsRef`がADDON/Rapid反映前で固定される）は1剤目（primary）の状態管理に起因していた。2剤目以降（node）は元々別の状態管理（`composeNodes[].block.rawFields`）を持ち、Phase 1監査記録§8.6で「node ブランチは ADDON 込みで rawFields を保存するため保持されると読める」とコードから推論されていた。今回の実機確認により、この推論がFACTとして確定した。
2. **経路Bの根拠**: H-1修正（コミット`37a9262`）は`handleSToggle`の両分岐（トグルON/OFF）でraw基点への並行更新を実装済み（Phase 1監査記録§8内の該当箇所）。実機でS先頭文の内容が3状態（ON時・OFF時・ベースライン）すべてで文字列完全一致または期待どおりの変換のみであることを確認し、コード変更が意図どおり機能していることを裏付けた。
3. **経路Cの根拠**: Phase 1監査記録§8.11追記で「persona種別変更も`reapplyPersonaToAllBlocks`を通ることをコードで確認した」とFACT化されていたが、実機での動作確認はPhase 1実装セッション時点では未実施だった。今回、3種別（簡潔/丁寧/やさしい）への切替すべてでADDON文の欠損・重複がないことを確認し、コード上のFACTが実機でも成立することを確認した。
